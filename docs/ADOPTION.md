# 사내 도입 체크리스트

## 범위를 먼저 고정

이 저장소는 UI 기반입니다. 인사평가시스템, AWS 인프라, SSO 서버, 개인정보 처리 시스템 자체가 아닙니다.
면접에서 확인하지 않은 조직·인프라는 가정하지 않습니다. 실제 도입 시 시스템 조사와 회사 승인이 필요합니다.

## 운영 전 승인 기준

- [ ] 대표 사용자가 평가 생성 → 대상자 지정 → 입력 → 제출 → 반려/승인의 업무 흐름을 검증했다.
- [ ] 실제 인증과 서버 권한 검사를 연결했다. 숨김/disabled UI만으로 접근을 제한하지 않는다.
- [ ] 개인정보 최소수집, 보존·삭제, 마스킹, 감사 이력 정책을 승인했다.
- [ ] 장애·저장 실패·중복 제출·네트워크 단절에서도 작성 내용을 보존한다.
- [ ] 키보드, 한국어 IME, 화면 확대 200%, 스크린리더, iOS/Android를 실제 지원 범위에서 검증했다.
- [ ] 표의 실제 데이터 규모로 성능을 검증했다. 현재 Table은 가상 스크롤/서버 정렬 그리드가 아니다.
- [ ] 폰트·아이콘·기반 라이브러리 라이선스와 회사 코드 반입/소유권 정책을 확인했다.
- [ ] 패키지 버전, 변경 승인, 회귀 테스트, 롤백 절차와 담당자를 정했다.
- [ ] 단일 개발자 부재 시 다른 담당자가 빌드·배포할 수 있도록 인수인계를 검증했다.

## 현재 UI 검증 경계

React와 Vue는 CSS를 공유하지만 API가 완전히 같지 않습니다.
Vue 통합 페이지에서 검증된 폼·상태·다이얼로그·트리부터 사용하세요.
카탈로그의 설계 중 항목은 아직 지원 기능이 아닙니다.
Chromium 자동검사 통과는 Safari·Firefox·보조 기술까지 인증한 결과가 아닙니다.

## 회사 업무는 데모와 분리

예제의 이름·조직·숫자는 가상입니다. 실제 인사 데이터를 공개 문서 사이트에 넣지 마세요.
데모에서 “저장”은 메모리 상태 변경일 뿐 영구 저장이 아닙니다.
운영 애플리케이션과 공개 문서의 데이터·계정·배포 경계를 분리하세요.
