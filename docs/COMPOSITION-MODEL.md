# CHEESE의 패턴·템플릿 구성 기준

## 목적

구현 관점의 `composite component`도 제품에 직접 설치해 사용하는 정식 컴포넌트입니다.
다만 문서 탐색에서는 반복되는 동작 조합을 **패턴**, 페이지 수준의 뼈대를
**템플릿**으로 구분합니다. 직원 관리나
오디션처럼 특정 업무의 데이터·정책을 포함한 완성 화면을 라이브러리로 옮기는
것이 아닙니다. 기본 컴포넌트와 같은 토큰, 접근성, 상태 및 패키지 경계를 따릅니다.

| 단계          | 제공하는 것                                         | 사용자가 연결하는 것                                |
| ------------- | --------------------------------------------------- | --------------------------------------------------- |
| 기본 컴포넌트 | Input, Select, Button, Dialog, Avatar, DataTable 등 | 값과 동작                                           |
| 패턴          | RecordCollection, PeoplePicker, FormActions 등      | 데이터, 상태, 콜백과 슬롯                           |
| 템플릿        | AppShell, ListPage, DetailPage, FormPage 등         | 패턴과 업무 콘텐츠                                  |
| 적용 예제     | 인사평가, 직원 관리, 오디션 관리                    | 가상 데이터와 예시 정책; 라이브러리에 포함하지 않음 |

기존에 검증한 컴포넌트를 지우거나 새 컴포넌트로 중복 구현하지 않습니다.
패턴·템플릿 카탈로그는 기본 컴포넌트 문서와 연결되며 실제 내부 조합을 표시합니다.
CSS 레이아웃만 담당하는 구성요소는 존재하지 않는 하위 컴포넌트를 사용한다고
표시하지 않습니다.

## 실제 재사용 경로

```text
Avatar ───────────────────────────────→ UserIdentity
Card ─────────────────────────────────→ StatCard → StatGroup
NavigationList + Dialog ───────────────→ AppShell
SearchInput + Select + Button ─────────→ FilterBar ─┐
Button + 처리 상태 ────────────────────→ BulkActionBar ├→ RecordCollection
DataTable (선택·정렬·페이지·서버 요청) ────────────────┘

AppShell + ListPage + StatGroup + RecordCollection
  ├ 직원 관리 (직원 데이터·조직 필터·변경 API)
  └ 지원자 관리 (지원 데이터·분야 필터·검토 API)
```

직원 관리와 지원자 관리의 메뉴를 하나의 가상 제품으로 섞지 않습니다.
다른 예제로 이동하는 링크는 제품 메뉴 밖의 예제 탐색에 둡니다.

## 상태와 서버 연결

- `RecordCollection`의 query, selected, filters는 사용하는 화면이 관리합니다.
  검색과 조건 변경은 첫 페이지로 돌아가며, 선택은 명시적으로 해제할 때까지 유지됩니다.
- 로컬 데이터를 사용할 때는 외부 조건 필터만 화면에서 적용하고, 검색·정렬·페이지
  계산은 DataTable에 맡깁니다. 서버 모드에서는 같은 작업을 서버가 수행하며 응답을
  클라이언트에서 다시 필터링하지 않습니다.
- `loadRows(query, { signal })`은 DataTable로 전달합니다. 로더는 필터가 바뀔 때만
  새로 만들고, AbortSignal을 실제 요청에 전달해야 합니다. 불필요한 요청 재실행을
  막기 위해 React는 `useCallback`, Vue는 안정적인 함수 참조를 사용합니다.
- 검색 결과 수를 모를 때는 `resultCount`를 생략합니다. 전체 데이터 수를 검색 결과
  수로 표시하지 않습니다.
- 일괄 처리의 권한, 멱등성, 부분 실패 결과와 재시도 대상은 서비스가 결정합니다.
  패턴은 전달된 결과를 표현하며 데이터가 저장됐다고 임의로 판단하지 않습니다.
- `NavigationList`/`AppShell`의 이동 콜백은 이벤트를 제공하므로 라우터와 미저장
  변경 확인을 연결할 수 있습니다. 인증·인가를 수행하는 컴포넌트가 아닙니다.

## 스타일 원칙

패키지 CSS가 컴포넌트의 표면, 글꼴, 크기, 포커스와 반응형 동작을 정의합니다.
예제 CSS는 화면 배치와 간격만 담당합니다. 예제에서만 보기 좋은 버튼·테이블·입력창을
별도로 덧칠하지 않습니다. 흰색 표면, 중립색 경계와 Cheese Gold 강조를 공유하며
오류 등 의미 전달이 필요한 경우에만 상태 색상을 사용합니다.

## 입사 후 연결해야 하는 것

이 라이브러리는 그룹웨어의 UI 기반이지 완성된 업무 서버는 아닙니다.

1. 사내 SSO와 서버 측 권한 검사, 조직·직원 원천 데이터.
2. 실제 API 스키마, 응답 검증, 수정 충돌 처리와 변경 이력.
3. 평가·심사 프로세스와 개인정보 조회·다운로드 범위.
4. 저장 중 이탈, 세션 만료, 네트워크 중단 시 복구 정책.
5. 대상 기기·브라우저와 실제 사용자의 키보드·보조기술 검증.

`PageError`나 `SessionExpired`를 표시하는 것만으로 서버 복구나 인증이 구현되지는
않습니다. 샘플의 메모리·sessionStorage 저장을 실제 운영 저장으로 사용하지 마세요.
패키지 배포 방식과 도입 검증은 README와 ADOPTION.md를 따릅니다.
